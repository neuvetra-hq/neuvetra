# Private passage research experiment

This opt-in service replaces the lexical question gates only in its own entry point. The earlier `research/` engine, releases and evaluations remain separate. It is a local U.S. purchased-electricity conceptual research experiment, not numerical accounting, company diagnosis or legal advice.

The pipeline sends the whole approved paragraph catalog to semantic planning, expands approved context dependencies, drafts atomic cited claims from complete selected paragraphs, then asks a fresh-context model call to assess support, relevance, qualifications, scope and completeness against the original question. Planning identifies the minimal material requested facets, rather than creating facets for ancillary background. Drafts contain exactly one answer group per planned facet, with text and unique eligible passage IDs. The server assigns globally unique claim IDs in canonical planned-facet order, preserving claim order within each group; models do not assign draft IDs. Each claim must link to its facet's planned source context and at least one direct primary passage. The server resolves full pinned paragraphs, attaches mandatory qualifications/dependency references, and displays no draft until the checks pass. There are no model tools, external retrieval services or streaming responses.

Output space is shared across facets: at most six claims overall, 400 characters per claim and 1600 claim-text characters overall. With N facets, each receives at most floor(1600/N) text characters and ceil(6/N) claims, subject to those global limits. Missing, empty or duplicate groups, wrong-facet references and exceeded budgets withhold the whole answer. The critic independently assesses the proposed decomposition against the original question, including unrepresented clauses; every facet also needs an exact support/completeness verdict bound to its own claim IDs, alongside every claim's support/qualification verdict. A global pass cannot override a failed or absent facet verdict. Final claims render in planned facet order. These bindings control coverage structure, not semantic truth; optional retrieved passages need not all be cited.

Drafting targets are 75% of the hard character ceilings: 300 per claim, 1200 overall and floor(0.75 × each facet's hard text budget). This gives the model headroom without changing any rejection boundary or truncating generated text. Hard limits remain enforced even for a one-character overage. The critic receives the server-assigned IDs and must bind its verdicts to those exact claims.

The original experiment required models to retype supporting quotations. Private diagnostics demonstrated output truncation, duplicate support entries and inserted ellipses; the compact contract removes that copying step. This removes a quote-containment check that established copying fidelity, not entailment. Source hashes, exact full paragraph text, locators, reference checks and mandatory dependencies remain server controlled. Compact limits reduce output pressure but do not guarantee every response fits its stage's output ceiling; truncated output is always withheld as `provider_truncated`, and an empty draft is withheld as `draft_empty`.

A valid citation does **not** establish entailment. The final reviewer is another model call, not independent professional assurance. Incorrect planning or a reviewer that wrongly accepts a claim can still produce an irrelevant or false answer with real citations. A controlled lying-reviewer test deliberately demonstrates this limitation. Relational questions require a source-supported explanation, and each clause must preserve the source's subject, category, relation and quantifiers; prompts cannot guarantee this fidelity. Independent source review, held-out semantic evaluation and consequential-use review remain necessary. Failed mechanical checks and model rejections are safe failures; passing mechanical checks is not an accuracy score.

Planning uses Sonnet 5 with thinking disabled and 1200 output tokens by default. Drafting and verification use Opus 5 with adaptive thinking, high effort, omitted thinking display and an 8192-token total output ceiling per stage, including thinking. A small controlled verifier comparison at 4096 tokens motivated that reviewer profile. A later end-to-end run still found drafting errors and likely reviewer false negatives; changing only the drafting profile is a pending comparison, with prompts, schemas and rejection boundaries unchanged. Neither the 8192 ceiling nor reasoning-enabled drafting is a demonstrated accuracy improvement. The parser discards known thinking/redacted blocks and signatures and accepts exactly one final text JSON block from the configured model. Unknown blocks, wrong-model responses, refusals and incomplete output fail closed. No thinking content or signatures enter the answer or parsed-stage traces.

Every claim is evaluated only against its own cited passage dependency closure. Other context can expose contradictions or omitted aspects, but cannot provide uncited support. The verifier receives the explicit allowed passage IDs for each server-assigned claim; essential conditions and modality must be present in the claim itself. This scopes the review but cannot prevent a model from making a mistaken entailment judgment.

Generated numerical literals must be present in the cited source context or its approved edition metadata. A separate output policy withholds quantitative emissions/activity/factor amounts and numerical result predicates, including common number-word forms, even when a matching number exists in evidence. Scope 2 labels, source years and unit names without an amount remain allowed. This conservative check is independent of the model verdict; it does not prove all numerical semantics or detect every obfuscated expression. Original reviewed paragraphs may themselves contain source figures; displaying them as evidence does not perform or authorize a calculation.

## Evidence and controls

Release schema 2 binds source bytes, an external normalized-page extraction artifact, page hashes, Unicode code-point offsets, complete passage text hashes and independent review decisions. Runtime verifies those bindings before the pipeline and rechecks them before display. It does not independently re-extract PDF text on each request or protect against a malicious concurrent filesystem operator. Review must establish that the extraction matches the original and that usage rights cover the selected paragraphs. Approved dependency graphs must resolve and be acyclic.

Source authority is restricted by server policy to approved EPA guidance for U.S. conceptual research. A model plan cannot expand allowed actions, access unapproved passages, choose a tenant or run calculations. The system still relies on semantic planning and review to recognize the original request and generated claim scope; model labels alone cannot establish that those judgments are correct.

One pipeline runs at a time. Provider-owned preflight uses the actual configured stage profile and complete serialized request against 22,000 UTF-8 bytes; it never truncates evidence. Transport has a 90-second timeout bounded by the overall 150-second cancellation signal; the HTTP idle limit is 160 seconds. Cancellation prevents subsequent stages. The request lock remains until underlying work settles if a faulty adapter ignores cancellation. Each provider attempt reserves at least $0.50, shared across all stages, up to 30 attempts and a $15 reservation envelope. A full answer uses three attempts; failures and uncertain calls count and are not retried. These are conservative reservations, not measured invoice amounts. Counters reset on process restart: the coordinator must carry forward the remaining batch budget.

## Running and checking

From `apps/site-api`, run `bun run start:research-passages`. The entry binds `127.0.0.1:3012`; starting it is an explicit coordinator action after stopping any service on that port. It is disabled by default. Neither tests nor imports start a server or make real model calls.

Configuration uses `RESEARCH_PASSAGES_RELEASE_PATH`, `RESEARCH_PASSAGES_RELEASE_SHA256`, and `RESEARCH_SOURCE_ROOTS` (JSON array of absolute approved source/extraction directories). Paid calls additionally require explicit `RESEARCH_PROVIDER=anthropic`, `RESEARCH_ANTHROPIC_API_KEY`, and the existing `RESEARCH_MODEL`, `RESEARCH_MAX_CALLS`, `RESEARCH_MAX_OUTPUT_TOKENS`, `RESEARCH_MAX_SPEND_USD`, `RESEARCH_CALL_RESERVATION_USD` controls. The legacy `RESEARCH_MODEL` remains `claude-sonnet-5` for the planner only; other values disable the provider. `RESEARCH_MAX_OUTPUT_TOKENS` defaults to 1200 and caps only planning. Drafting and verification profiles are fixed to Opus 5/adaptive/high/8192. Other defaults are 30 attempts, $15 maximum and $0.50 per-attempt reservation. `RESEARCH_PORT` and loopback-only `RESEARCH_ALLOWED_ORIGINS` default to 3012 and the Site's port 5174. Merely supplying a credential never enables the provider.

`GET /research/status` and `POST /research/answer` retain the Site response structure with `answer_mode: "passage_grounded"` and a fixed `reason_code`; no raw model rationale, local path or provider error is returned. `provider.model` identifies generation; `provider.stages` supplies the actual per-stage models, thinking modes and output caps. The health `limits.max_output_tokens` is the maximum stage ceiling, 8192. `evidence.excerpt` contains the server-controlled full cited paragraph. `claim.evidence_ids` and qualifications include approved dependency closure.

Run `bun test src/research-passages` and `bun run typecheck`. Unit/provider tests use synthetic source text and mocked network responses. Real source loading, semantic QA and any paid evaluation are separate evidence and must be reported separately.
