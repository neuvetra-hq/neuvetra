## Key Takeaways

1. **Parallel framework to corporate accounting.** The Project Protocol is not a corporate inventory tool — it quantifies GHG *reductions* from specific mitigation projects (e.g., renewable energy installations, fuel switches, afforestation). The unit of analysis is a project activity, not a company.

2. **Two baseline procedures for estimating what-would-have-happened emissions.** The project-specific procedure identifies a scenario-specific baseline through a structured barrier and net-benefits analysis. The performance standard procedure derives a benchmark from a pool of all comparable technologies or practices — it can be applied to many similar projects and avoids project-specific subjectivity.

3. **Additionality is embedded, not tested separately.** Unlike some carbon offset programs that require an explicit additionality test, the Project Protocol incorporates additionality implicitly through its baseline estimation procedures. A project is additional if it differs from its identified baseline scenario.

4. **A sixth accounting principle: Conservativeness.** The Project Protocol adds a sixth principle beyond the Corporate Standard's five — Conservativeness. Where data and assumptions are uncertain and where cost of reducing uncertainty is not worth the accuracy gain, conservative (downward-biased) values must be used. This reflects the asymmetric risk of over-crediting GHG reductions.

5. **Relationships to CDM and ISO 14064.** The protocol is designed to facilitate use for Kyoto Protocol Clean Development Mechanism (CDM) projects and is compatible with ISO 14064 (project standard). A mapping between the three frameworks was committed to on the GHG Protocol website.
