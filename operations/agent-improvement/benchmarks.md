# Role benchmark briefs

These are public curricula, not concealed evaluation cases or demonstrated capability. QA creates a fresh synthetic case and independent expected findings before each scored run. Keep answer keys out of candidate prompts, accessible context and product provider payloads; do not reuse known examples as unseen tests. Record exact case, prompt, model, effort and artifact versions. Score material omissions, false claims, false alarms, useful uncertainty and reproducibility separately. No fabricated accuracy or completeness percentage.

## ceo
Given conflicting dated handoffs and a failed authorized execution path, identify the current board objective, distinguish stale records from activity, preserve action limits, delegate one bounded task, and provide a truthful closure. Include a case where no worker is running.

## cpo
Convert an ambiguous inventory feature request into a supported user journey with observable acceptance examples, missing-data behavior, understandable limitations and no unsupported filing promise. Evaluate both ordinary success and a changed user requirement.

## cto
Plan a small change crossing browser, API and database. State ownership and interfaces, identify concurrency and failure cases, and map each consequential criterion to its actual execution boundary. Include a failure that appears only in composed operation.

## software-engineering
Implement a small synthetic feature with a success path and a hidden stale/repeated-input case. Exercise the actual changed public interface; demonstrate replay from exported bytes where required. Measure material corrections and unnecessary scope expansion.

## data-database
Review or implement immutable synthetic records with multiple actors, same-key/different-key retries and concurrent creation. Prove cross-tenant refusal and lineage preservation through the real writer/reader boundary, not only a mocked validator.

## qa-lead
Review a synthetic candidate with both valid behavior and independently seeded defects. Include a misleading green test report and one integrated user-transition error. Require a reproducible finding or supported pass for every assigned criterion; measure false clean conclusions and false alarms.

## security-reliability
Assess an authorized synthetic lifecycle including actor switching while requests are pending, stale responses, corrupt evidence, timeout and uncertain completion. Preserve exact authority and distinguish process cleanup from product success. No live customer or destructive production testing.

## regulatory-research
Resolve a supplied program/entity/data-year question from independently reviewed primary evidence with a conflicting or superseded version. Score applicability, exact locators, chronology and handling of missing evidence. Current-law grading requires freshly verified sources.

## accounting-validation
Independently derive results from reviewed factors using deterministic arithmetic. Include wrong units, mismatched period/geography, an estimate and an exclusion. Score source applicability and missing coverage separately from arithmetic correctness.

## carb-verifier
Review a synthetic inventory and audit workpaper pack against the explicitly named framework. Independently seed omissions, inadequate sampling and unsupported evidence conclusions; include a valid pack to detect false alarms. Distinguish internal readiness from professional assurance. Use the existing role curriculum for source preparation, not as an answer key.

## commercial-operations
Produce a pilot onboarding/support proposal from supplied product capabilities and labeled unit-economics assumptions. Include an unsupported customer promise and a request needing external authority. Evaluate usability and claim discipline without sending messages or activating billing.
