# Continuation4 revisit capture preparation

`M78-CONT4-REVISIT-CAPTURE-PREP-01` adds an offline-reviewed public capture seam for a later private continuation4 revisit wrapper. It does not authenticate, execute a hosted revisit, read credentials, or write an official observation during preparation.

## Passive capture contract

The capture fetch calls its supplied transport exactly once with the original URL and `RequestInit`, then returns the exact original `Response` without reading it. For successful GETs under the exact workspace application path, it consumes a clone asynchronously. Auth-host responses are never cloned or retained, and no headers, request bodies, tokens, or credentials enter the capture. Clone or reconstruction failures are accumulated instead of thrown from fetch, allowing the unchanged core journey to complete logout. After a passed core revisit, any capture failure produces a separate failed `revisit_capture` result and no full-success claim or observation.

Each response is limited to `10,000,000` bytes, matching the unchanged M78 response bound. At most `1,024` responses and `128,000,000` aggregate response bytes are admitted; the aggregate cap matches the unchanged main-journal byte cap. A shared counter reserves every clone chunk before it can be hashed or retained, and the clone reader is cancelled immediately when either byte bound fails. Export, statement, report, snapshot, and archive bodies are streamed into SHA-256/byte-length observations and discarded. Bounded JSON is retained only for registers, Scope 1, proofs, and the legacy records needed to reconstruct state. Repeated successful routes must be byte-identical. Every pending clone is drained even when the core revisit fails, while a capture error never masks that core result.

## Observation reconstruction

The builder independently decodes fresh captured Scope 1 plus corporate, gas, mobile, fleet, diesel, equipment, and fugitive registers. It reconstructs the exact download and M78 export maps from observed route bytes and rebuilds the legacy snapshot from captured legacy JSON/download responses. Exercise journal state is not an input. It requires the 173 unique source pins, a gate pin, capture chronology, and a closed revisit journal binding. The new observation writer uses exclusive creation at `.superpowers/m78-continuation4-revisit-observation.json`.

Candidate 1 passed its author suite but failed independent review: aggregate bytes were added only after each clone had been fully buffered, so concurrent retained JSON could exceed the claimed bound, and pending clones were not drained when the core returned a failure. Candidate 2 reserved the shared aggregate budget per chunk before retention, cancelled a clone immediately on a byte-bound error, and drained all clone tasks for both successful and failed core results. It was rejected after a real-decoder QA fixture exposed that six register decoders return promises while the builder treated them as synchronous values; the identity-decoder author fixture had hidden the defect. Candidate 3 awaits every default decoder and retains support for synchronous injected test decoders.

Combined candidate3 tests pass `8/8` with `40` assertions. They verify one underlying call, unchanged init, original Response identity and unread body, zero auth capture, duplicate-response refusal, concurrent aggregate, per-response and request-count boundaries, exact positive observation reconstruction, missing-response refusal, cleanup completion before capture failure, pending-clone drain after core failure, and exclusive observation writing. A separate local native fixture uses every default asynchronous decoder with response-shaped state and reconstructs nonempty dynamic fugitive-download and M78-export maps; it reads no hosted journal and performs no network, credential, or database operation. Strict targeted TypeScript passes with library declaration checking skipped because the repository's unrelated PGlite declarations require unavailable Emscripten globals. The transport tests use Bun's actual `Response.clone()` implementation with an injected transport, so no loopback network server is needed.

The observation format and limits require independent QA before a private wrapper or hosted execution may use them. No source among the 173 pinned continuation4 files, core journey, inner gate, closed lifecycle candidate, database, provider, Git state, or official journal was changed.
