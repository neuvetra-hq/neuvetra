## Preserved first-review findings

**M65-QA-F01 — fingerprint placeholders were not substituted.** The original alphabetic-only placeholder expression omitted digits in keys such as `sourceSha256`; the same restricted unresolved-placeholder guard missed them. An independently executed renderer test failed because the workbook hash was absent and literal placeholders remained. CTO expanded both TS substitution and TS/SQL guards to alphanumeric keys. Final independent renderer and native persisted-report checks pass with actual fingerprints and no unresolved placeholders. This was a product defect, not a test fixture issue.

**M65-QA-F02 — transaction-start review time could precede an earlier serialized report capture.** Source review found M64 review used transaction-start `now()` while report capture used wall-clock time after the company lock. A review transaction beginning first but waiting behind report creation could receive an earlier timestamp, causing the legitimate absent-review report to fail the temporal lineage check. CTO added a narrowly scoped replacement of the review function in migration11: one millisecond wall-clock timestamp captured immediately after acquiring the company lock is shared by the new decision and audit. Migration10 bytes and prior rows remain unchanged. The old implementation was not executed by this reviewer before that repair. The final independent native test proves a review is actually blocked in `pg_stat_activity`, creates the absent-review report while holding the company lock, then permits the review to commit and verifies the original report bytes remain valid. CTO also reported a separate actual blocked-review regression pass.

Two QA harness corrections remain visible in the execution record: an early decoder fixture used a fake template hash after the real decoder pin was added; the fixture was corrected. The first native run passed nine behavior tests but failed both baseline comparisons because the frozen per-row serialization used local time and the runtime driver used UTC. Repeating comparison in the original timezone resolved both, without product changes. These are not attributed to product defects or hidden as first-pass successes.
