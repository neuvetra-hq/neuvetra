# Continuation4 lifecycle evaluator preparation

`M78-CONT4-LIFECYCLE-REVIEW-PREP-01` provides an offline evaluator for two honest admissions. An exercise-only result may be issued after a closed exercise and before restart. A full-lifecycle result additionally requires a fresh actual restart attestation, a closed zero-write revisit, and a separately pinned read-only observation of the revisited state. The evaluator never authenticates, calls a host, or opens a database.

## Admission boundaries

The evaluator uses the unchanged core journal parser and `cleanM78ContinuationJournal`. It pins the independently accepted continuation4 baseline result, then requires its exact journal byte prefix, event count, head, and completion time. The exercise must contain the exact ordered 37-name recipe derived from the accepted decoded baseline. Each intent/outcome/verified triple must be contiguous, status 201, and have a distinct verified identity that resolves to the decoded current Scope 1/register graph. The five report identities must equal the five decoded report IDs. It independently decodes the final state and requires one process version, two inventory versions, two process reports, three inventory reports, ten source-union rows, reviewed process/inventory successors, and exact company total `126850.17632025`. Accepted baseline register history and export bytes must remain present, and legacy state must remain equal.

Diagnostics form one continuous hash chain with exact `baseline,exercise` or `baseline,exercise,revisit` phase order. Every phase resets request ordinals, copies the exact baseline parent metadata, uses Bun fetch with pooling disabled (`keepalive:false`) and zero retries, pairs every request with response headers, has eight token and eight logout requests using POST, accepts only the expected response status for each route/method, and records `0/37/0` application POSTs. The baseline diagnostic phase is byte-bound to the accepted baseline diagnostic hash/head/event/request counts. Each later diagnostic request count must match its main-journal phase and each diagnostic phase must bracket the corresponding journal phase.

Full admission reuses the original restart validator for strict exercise-closure, restart-request, actual-startup, and observation chronology. A board or review pause between exercise and restart is allowed; freshness is measured from the completed restart observation to the revisit start and is limited to 15 minutes. The evaluator does not trust `exactRetainedState` alone: a separate hash-pinned revisit observation must decode to the exact exercise Scope 1 state and carry equal registers, downloads, M78 exports, and legacy state.

## Review and validation

Candidate 1 was rejected in independent review. It did not bind baseline diagnostics, method/route/status/auth counts, all recipe names and identities, retained artifacts, an independently decoded revisit observation, or restart freshness. Candidate 2 repaired those findings but incorrectly measured freshness from exercise closure, which would reject a legitimate restart after a review pause. Candidate 3 kept strict restart chronology and passed its first exact review, but a later supplemental mutation swapped two same-kind source-version identities; uniqueness and current-graph membership alone admitted the wrong identity for each named operation. Candidate 4 binds every recipe name to its exact intent route and the typed current record returned for that operation: corporate/source/discovery/process/inventory versions, their corresponding reviews, and all five reports. The original targeted suite remains `14/14` with `863` assertions, strict combined TypeScript passes, and the independently authored swap reproduction is now rejected at operation 4. Candidate 4 requires a new exact independent receipt before use.

This is preparation for later closed hosted evidence. It does not claim an actual continuation4 exercise, restart, revisit, or hosted acceptance. No network, authentication, database, credentials, Git, existing baseline evaluator, or closed source-preparation artifact was used or changed.
