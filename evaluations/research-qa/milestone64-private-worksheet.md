## First-review failures and resolution

**M64-QA-F01 — release blocker, repaired and retested.** The first real driver/API run returned422 for a valid initial worksheet. Both domain mutations passed `JSON.stringify(input)` to a JSONB-typed placeholder; postgres3.4.9 encoded the serialized string again and SQL received a scalar. A direct `jsonb_object_keys` probe established the cause. CTO changed both save/review bindings to serialized-text `::text::jsonb`. Real API saves, reviews, retries and all subsequent native checks passed. In-memory-only tests had missed this behavior.

**M64-ACC-F01 — accounting review blocker, repaired and independently retested.** The accounting reviewer found intermediate NUMERIC division losing a final decimal near62499.999 and999999.999, causing stored-result verification to fail. CTO replaced decimal divisions with exact decimal multiplication and integer `div`. QA restored the dedicated baseline before applying the repaired migration and independently passed both published cases and novel neighbors on PostgreSQL17.11. The original failure remains recorded; the unrepaired migration receipt is not accepted.

**Operator/harness findings — repaired before execution.** The initial upgrade helper checked output existence then wrote non-exclusively, and a receipt failure after commit could obscure completion. Root added exclusive receipt creation, sync and distinct committed/unknown-outcome errors. The first hosted journey helper omitted required Origin and expected403 for self-review while the implemented contract returns409; root corrected both. These were found by source review before this executor performed any hosted action. An intermediate QA assertion expected401 for authenticated uninvited/revoked users; the staging wrapper correctly returned403, so the test expectation was repaired. Downstream failures in the initial save-blocked run are not counted as separate product defects.
