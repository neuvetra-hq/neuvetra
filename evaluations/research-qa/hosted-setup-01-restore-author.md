## Delivered and tested

The paired backup API captures the application inventory and tenant read probes in one PostgreSQL17 repeatable-read, read-only transaction. It exports that transaction snapshot for the supplied dump transport and captures the inventory again before completion. The DPAPI CurrentUser archive contains the custom dump, source inventory, source snapshot-token hash, referenced synthetic Auth UUID stubs, `auth.uid()` definition and explicit actor/company probe expectations. Public receipts contain hashes and boundary flags, not application rows or credentials. The custom dump and decrypted bundle travel in memory; no plaintext dump or snapshot file is written. The restored local database necessarily contains the application data and must remain in the authorized private local cluster.

The absent-target-only restore entrypoint accepts exactly `127.0.0.1:55479`, `supabase_admin`, and `hosted_setup_restore_<13-digit-time>_<8-hex>` databases. It pins receipt, encrypted archive and pg_restore17 executable bytes; rejects unpaired legacy receipts before decryption; reserves a journal exclusively; verifies server identity, exact preexisting roles and membership; checks target absence; then uses CREATE DATABASE and single-transaction pg_restore with preserved ownership. There is no drop, replace, migration, or retry path. Failures leave their reservation and any created database for explicit reconciliation. Reusing a target or journal fails.

Comparison covers every application table including empty tables, all row hashes and counts, functions, columns, constraints/indexes/policies/triggers, schema/table ownership and effective ACL/RLS, sequences including their values, roles/memberships, dependencies and tenant read results. The only metadata normalization follows the inspected M80 v2 boundary: exclude provider default ACLs outside `neuvetra`/global scope and compare internal triggers as an ordered semantic multiset without generated names. It retains duplicates. The backup requires a positive member probe for every existing company represented in company_members and an outsider; a second synthetic company is not created or required. Native tests exercise two companies and an outsider.

## Root integration and limits

`createHostedSetupBackup` is an API accepting an already-authorized source connection and a dump transport. Root must supply the same validated source endpoint to both SQL and pg_dump17, verify TLS CA/hostname and pin pg_dump bytes, and pass the exported token unchanged to `--snapshot`, together with `--format=custom --schema=neuvetra --no-password`. Keep credentials only in the existing private runtime, never prompts, receipts or CLI output. Only root may do the actual hosted read after independent review. The API itself does not load credentials or establish a hosted connection. The supplied transport is a trusted boundary: a hash cannot prove its endpoint or command arguments. The eventual restore comparison must pass before treating the paired backup as preservation evidence.

Automatic approval review rejected adding a separate password-authenticated hosted transport wrapper, because this worker was authorized only for local synthetic execution and the proposal could export sensitive hosted data to caller-selected paths. No hosted execution was attempted. The rejected addition was not retried. Root owns the exact-target hosted transport and its separate review/approval boundary.

The earlier `backup-existing.ps1` archive has no same-snapshot inventory/Auth/role/probe companion. It cannot be upgraded into preservation proof by taking an unrelated later snapshot. Root must collect a new paired backup using one shared exported snapshot. Keep the old archive as diagnostic recovery evidence only. No actual hosted archive or credential export was read by this worker.

Local roles and memberships must already match the snapshot exactly. This helper never creates/alters cluster roles, provider accounts or provider configuration. Root must prepare the disposable cluster under a separately reviewed local role plan. Application foreign keys to anything other than scalar `auth.users(id)` fail closed. Only referenced UUIDs and the UID function are reconstructed; provider Auth accounts, passwords, sessions, configuration and object storage recovery remain excluded. Source/global default ACLs that pg_dump does not carry will cause comparison failure; do not waive or normalize them away. Snapshot consistency does not freeze concurrent sequences or schema changes; the before/after checks and restore comparison detect differences and refuse them. Capture during an operationally quiet interval.

The tenant comparison exercises database reads and access errors with unchanged baseline roles; it is not the separate full API/storage/export/job cross-company test or a hosted two-company demo. No hosted migration, rollout, deployment, invitation, source/method release, or board demonstration is claimed. Runtime failures must be reported using fixed recovery error codes, never raw driver output.
