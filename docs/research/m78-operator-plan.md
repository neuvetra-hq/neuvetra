## Failure and retry discipline

Before a consequential local migration, reserve an exclusive journal and flush a started record. Record reviewed migration, baseline/bundle hashes, clone identity and independent gate receipt. A transaction error is not a successful receipt. If COMMIT was attempted but acknowledgment or receipt persistence fails, label outcome unknown and inspect exact receipts/current inventory before any retry. If committed but receipt failed, never reapply. Existing receipts/targets refuse, rather than overwrite. No down migration, receipt deletion, history removal, or schema20-only image readiness claim against21. Root chooses a reviewed21-compatible recovery image or separately authorized pre-upgrade restoration.

Gate validation binds operator/reviewer distinct identities, exact migration and code review snapshot, baseline backup/restore hashes, populated21 forward-recovery proof and timestamps; a JSON attestation is not a cryptographic identity service. Local author rehearsal does not create hosted authority. Root's later hosted gate must refresh maintenance, deployment/checks and backup evidence and explicitly own the execution.
