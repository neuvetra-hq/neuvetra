# Next reliability work — proposal, not implementation

The original vocabulary gate and missing source-text representation are confirmed structural defects. The separate paragraph pipeline removes those constraints, but five retained live runs show that software validation and model agreement do not establish useful, accurate answers. The latest model-profile experiment did not pass. Current disposition: hold release, preserve evidence, keep the local provider stopped.

## Two distinct problems

1. **Correctable refusals.** Drafts can add unnecessary or overstated explanations, omit conditions or exceed structural bounds. Some reviewer refusals are also ambiguous or overly strict. Retrying the same question until it passes would obscure this behavior.
2. **Missed defects.** A reviewer can approve a claim with inadequate own-citation support or a missing prerequisite. A correction step triggered only by a negative verdict cannot repair a false approval.

## Bounded correction candidate

Keep the original question, planned facets and complete approved evidence. First parse and validate a review's complete structure, exact claim/facet IDs and citations separately from its approval decision. A well-formed, aligned negative review may permit one whole-answer redraft followed by a fresh whole-answer review. The new reviewer must not inherit the previous verdict as authority.

The candidate does not revise malformed verdicts, failed decomposition/scope/context, source errors, draft validation failures, transport errors, truncation or cancellation. It never silently deletes a rejected statement and releases the remainder. Any second failure withholds the whole answer. These eligibility details still require implementation and independent challenge; they are not an assurance that the first critic was right.

Successful paths would use three or five provider stages, with no network retry. Admission, counters and evaluator assertions must reflect the full possible path: a 30-stage allowance cannot promise eight five-stage questions. Any new evaluation budget must be declared separately, with all attempts counted.

The CTO measured candidate payloads offline against seven recorded run04 contexts. Complete revision requests were at most 17,461 bytes using the actual prior claims and compact failed-verdict flags; a maximum ASCII allocation reached 20,081 bytes. Escaped-character stress cases reached 29,681 bytes. The existing 22,000-byte check must therefore run before both added stages; evidence must not be trimmed to fit. These are offline feasibility measurements, not working correction results.

## False-approval benchmark

Before treating correction as a release improvement, freeze an independently reviewed claim-level set spanning the approved source families. Include supported claims and controlled changes to source subject, quantifiers, modality, prerequisite conditions, temporal coverage and citation closure. Distinguish direct support, modest synthesis, ambiguous wording and unsupported claims; adjudicate reviewer disagreements from the original document rather than changing labels to fit a model.

Compare reviewers and complete answer pipelines on both false approval and unnecessary refusal, while recording latency and actual usage. More reviewers may increase correlated mistakes or refusals; a larger model is not a substitute for this measurement. Preserve all original runs, exposed regressions and the two final fresh probes. The latter remain unrun because the preceding gate failed.

Independent accounting/legal review, broader rights clearance, durable cloud source storage and tenant/usage controls remain later release dependencies. This proposal does not authorize production answering or calculations.
