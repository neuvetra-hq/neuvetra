## Concrete controls

`m77-common.ts` pins the manifest and migration and extends original inventories with canonical per-row hashes, sequence definitions and sequence state. Comparisons preserve every old table, row, catalog entry, owner, ACL, role, membership and application default ACL. Old trigger fingerprints must match exactly, including the frozen M76 cross-family fuel guard. Sequence ACL sorting uses role names, rather than installation-specific role OIDs.

`m77-apply.ts` executes only the exact reviewed migration inside the caller's transaction and advisory lock. It locks original tables, validates canonical receipts and project identity, denies unsafe runtime roles and checks legacy containment. A successful append contains the same original content and rows, nineteen original receipts plus one new receipt, and exactly eight empty new tables. Startup never imports or runs migration commands.

`m77-backup.ts` binds the custom-format application dump to one exported repeatable-read snapshot. `m77-seal-backup.ps1` encrypts with Windows DPAPI CurrentUser, writes a new archive exclusively, flushes it and verifies decryption. Restore decrypts through a pipe; it does not write a plaintext bundle. Wrong dump hashes, role mismatches, existing targets and existing receipt/archive paths refuse the operation. `m77-restore.ts` creates a fresh isolated database, restores the application archive and verifies exact rows, content, catalogs, sequence states and runtime denial/read behavior.

`m77-recovery-manifest.ts` retains the frozen schema 19 content manifest and adds all M77 statement bytes and metadata, version exports, calculations, dependencies including explicit nulls, reviews, report HTML and snapshots, event reservations, heads, request records and audit records. Canonical table/id/part keys prevent duplicate entries.

`m77-replay.ts` validates receipts before replay. Schema 19 replay invokes the unchanged M73–M76 readers, routes and browser decoders directly; it never calls the current schema 20 readiness check against schema 19. Schema 20 additionally replays every retained M77 version, statement, report, snapshot and proof through the actual authority, routes and browser decoder. Read-only inventories before and after establish that replay did not mutate content or sequence state. Auth-provider recovery is explicitly excluded: the archive has application UUID dependencies and the scoped auth helper, not provider credentials or provider infrastructure.

`m77-upgrade.ts` requires distinct operator and independent reviewer identities, exact reviewed commit and migration, fresh observations of the same remote head and required checks, fresh maintenance confirmation, encrypted schema 19 backup, exact restore, independent historical runtime replay, and populated schema 20 encrypted forward recovery. Receipts must match actual file hashes. Stale observations, altered receipts, absent calculations/dependencies and mismatched content refuse the gate. Exclusive durable journals distinguish started, failed and uncertain outcomes; an uncertain or committed operation must not be retried blindly. The gate is an explicit reviewer attestation, not an identity authentication service.

Its final result is recorded below when available.
