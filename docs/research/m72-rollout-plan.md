## Recovery decision

The unchanged M68/schema14 image rejects the schema15 manifest on startup, readiness and each workspace request. It is **not** a compatible rollback image. Expect a maintenance interval between migration and the schema15 deployment. If deployment fails, preserve schema15 and all data, keep writes stopped and retry deployment of the same reviewed schema15 commit on the existing service. If that candidate needs repair, independently review the schema15-compatible repair before deployment on the same service. Do not drop new tables, delete reports, restore over live state, or rewrite receipts to make the old image pass. A failed local restore leaves its new clone for inspection; use another unique clone name for a later attempt.
