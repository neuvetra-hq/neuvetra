# M76 consumed-fuel evidence guard

The schema19 migration adds exactly one trigger to an earlier table: `m76_mobile_fuel_evidence_guard`, a BEFORE INSERT trigger on `neuvetra.mobile_diesel_evidence_reservations`. It invokes the new zero-argument `neuvetra.m76_mobile_fuel_evidence_guard()` trigger function. The guard checks only rows with `statement_kind='fuel'`, refusing an issuer/reference/year identity already reserved as a stationary-generator fuel reference in the same company. Other companies and ordinary distinct mobile evidence remain admissible. All old function bodies, columns, retained rows and ACLs remain unchanged. This deliberately extends the old table's trigger catalog; recovery comparisons must permit only this exact addition.

The new generator writer performs the reverse check against every retained mobile fuel reservation, including evidence used by an earlier corrected version. Both application writers use the existing company row fence, so the second concurrent claimant must observe the first committed reservation. No old reservation is released by correction. The root coordinator accepted this bounded additive constraint; independent native tests of both orders and concurrency remain required before release.

New stationary reservations pin two normalized identities: SHA-256 of `[lowercase issuer,lowercase meter label,'2025']` and `[lowercase issuer,lowercase reference,'2025']`, with `kind='meter'` and `kind='reference'` respectively. The same workpaper may reuse its retained keys. A correction reserves new identities while keeping previous ones; another workpaper cannot reuse any retained identity. Reservations identify consumed evidence, rather than supply deliveries, and do not authenticate user-entered statements. The one-generator stream cap remains a separate limit.

The primary key is `(company_id,kind,evidence_key)`. Qualifying the key by kind preserves both reservations when the reference and meter label happen to be equal. The reverse mobile guard must still observe the fuel-reference reservation in that case. Native author checks cover this single-field reference correction, rejection against both the previous and corrected reference, and rollback-only mileage controls in each direction. Independent QA separately exercises complete writers and concurrent claims.
