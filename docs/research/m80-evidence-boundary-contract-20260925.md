## HTTP and streaming

All paths are `/beta-api/workspaces/:companyId/evidence`. Enforce prospective beta DB identity, active admission, membership generation and non-tombstoned tenant on every request; mutation checks again at commit. Uniform 404 for unauthorized/nonexistent objects, 401 authentication failure, 409 conflicting request/state, 413 oversize, 415 type, 422 metadata, 503 unavailable dependency. No company-wide hash lookup before authorization.

- `POST /uploads`: strict <=4KiB JSON `{requestId,fixtureId,reportingYear,facilityId,sourceId,evidenceKind,periodStart,periodEnd,declaredBytes,declaredSha256,declaredMime}`. Validate against exact synthetic manifest; server assigns evidence/attempt IDs and opaque object key. No filename/path/URL/actor/scan/release fields. Same authorized request/fingerprint returns its original attempt; changed payload conflicts. Reserve company quota atomically: two concurrent uploads, 20MiB retained bytes, 5MiB/file, ten-minute upload lease. Count reserved plus retained bytes; release reservation only after durable completion or verified cleanup, so failed uploads cannot evade quota.
- `PUT /uploads/:attemptId/content`: raw `application/pdf`, identity encoding, streamed counting/hash and bounded first-byte sniffing; never multipart or whole-request buffering. Reject compressed bodies, empty/oversize streams, misleading length, MIME/magic disagreement, declared hash/size mismatch. Cancel reader and close partial writer on failure. Content-Length is only an early rejection hint. No PDF parsing/rendering before quarantine. Rejected metadata does not read the content body; storage errors abort and quarantine the attempt.
- `GET /:evidenceId`: safe state/provenance only; no keys, scanner raw output or content. `GET /:evidenceId/download`: authorized attachment, server-generated filename, no-store/nosniff; no public object URL. `DELETE /:evidenceId` records deletion intent and returns 202 until storage deletion is verified.

Retries never append to a partial object. A live lease has one writer; expired attempts become abandoned, with a new explicit attempt required. Completed identical PUT retry checks current authorization and stored completion receipt, consumes/verifies the bounded resent stream, and returns the same receipt without rewriting storage. Different bytes conflict; no digest-only claim substitutes for streamed verification.

## Quarantine, scanner and crash consistency

Object adapter: `createExclusive(key)`, bounded `write`, `seal`, `openImmutable(version)`, `stat`, `deleteExact(version)`, scoped orphan listing. Local root is an exclusive task directory outside web assets; server-generated keys only, no user paths, symlinks/reparse traversal or overwrite. Seal durably before committing metadata. Persist reservation first; after writing revalidate lease/tenant/generation, then atomically record observed hash/length/version plus quarantine event. Failed commit leaves an inaccessible orphan, never a readable success. No database/filesystem atomicity is claimed.

State machine: `reserved -> uploading -> quarantined -> scan_pending -> verified_clean` or `rejected`; scanner timeout/error/unknown remains `scan_pending` with blocking reason. A leased worker/operator invokes scanning; no imaginary scheduler. Receipt must bind exact object version/hash/size, attempt nonce, scanner engine/signature versions, verdict and time. Only worker authority can finalize it through a revision/nonce compare-and-swap; this separate capability is unavailable to the HTTP runtime. Replay/stale receipt cannot override deletion/revocation or a newer scan. Missing, malformed or simulated verdict cannot produce `verified_clean`. A clean malware result alone does not validate PDF structure: sandboxed structural validation must also pass before real release; unsupported/encrypted/active-content PDF is blocked under the initial policy.

**Local functional branch:** exact manifest bytes may enter `synthetic_fixture_verified`, explicitly distinct from `verified_clean`, with `scannerAssurance: not_established`, `realDataEligible:false`. Only those exact fixtures can download in the local profile. Injected scanner cases exercise transition refusals but never prove malware safety; default scanner is unavailable. Hosted verified-clean download remains unimplemented/gated. Signature sniffing alone is not malware or structural validation.

Before download, open the pinned immutable version, verify full <=5MiB bytes/hash against authoritative metadata, recheck admission/generation/state, then serve the verified bytes; no unverified prefix escapes. Local bounded download buffering is acceptable. Revocation before this authorization point denies; an already authorized transfer may finish, but subsequent requests deny. Record that limit instead of promising instantaneous recall.

## Recovery, deletion and tests
