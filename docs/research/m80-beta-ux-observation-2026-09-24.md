# Scope 1 invited beta: observed website gaps

Coordinator read-only browser review, 2026-09-24, https://www.neuvetra.ai/. Existing signed-in access loaded automatically. The reviewer opened a separate background tab and selected the Scope 1 view; no form values, saved records, sign-out, invitations or deployment were changed. This is a usability observation, not a numerical, security or full accessibility acceptance.

## Observed current state

- Browser title and header identify private staging. The banner explicitly permits synthetic company records only. Keep these restrictions until real-data beta gates are met; a cosmetic rename cannot release the product.
- Thirteen peer workspace choices include corporate coverage, Scope 1 inventory, several source registers, and five electricity/example views. At 1280px width these occupy three navigation rows before the main content.
- Corporate coverage opens a saved synthetic group with 104 recorded findings. Scope 1 shows 10 discovered sources, zero unresolved workflow findings, 11 release findings, and a wider-corporate-gap section with 82 items. These counts have different scopes; they must not be presented as interchangeable defects or a single beta readiness percentage.
- Scope 1 displayed 126850.1763 kg CO2e, gas/source/facility/entity detail, and explicit round-once/estimate limitations. This observation confirms display only, not independent recalculation.
- Numerous location, evidence, process and gas sections start expanded, repeating long synthetic reference text and internal IDs. The page requires substantial scrolling before saved reports and correction actions.
- Action text such as 'Save current successor', 'retaining the combined inventory' and 'seven-gas discovery' assumes familiarity with implementation/accounting concepts. There is no obvious feedback route in the inspected views; other pages were not exhaustively inspected.

## Bounded beta acceptance recommendations

1. Offer a primary journey: company and reporting year -> locations and sources -> activity and evidence -> review gaps -> draft report. Keep advanced registers reachable through contextual links.
2. Start invited users with their authorized company workspace, not prefilled demonstration records. Separate examples clearly and never copy synthetic declarations into real reports.
3. Prioritize actionable Scope 1 gaps with a plain-language explanation, affected source and next action. Keep release/system blockers distinct from customer missing-data tasks and future Scope 2/3 coverage.
4. Use readable source names and formatted totals/units. Keep original IDs, precision, factors, versions and calculation details available for traceability. Never change calculation or rounding policy merely to simplify display.
5. Default long evidence/detail panels to summaries with explicit expand controls; show progress and the next required action. Preserve unknown and unsupported statuses, and do not silently default source applicability.
6. Provide clear draft/beta labels, supported-source limits, evidence requirements, save feedback, correction history, report access and a visible feedback/support route.
7. Before invitations, independently test two distinct company accounts, invitation/sign-in behavior, evidence access, expected calculation outputs, missing/invalid inputs, report export and a complete first-use rehearsal. Recheck desktop and narrow-screen layouts and keyboard operation on the implemented candidate.

The board's near-term target is a free invited beta for 2–3 supported-profile companies, not payments or full corporate Scope 1–3 launch. Numerical validation remains our responsibility; knowledgeable beta users add real-world comparison evidence. Company types are awaiting board clarification. Product task owns implementation, final acceptance records and Git publication.
