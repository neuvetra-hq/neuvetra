## Fixed development contract

**Targets and identities.** Before writes, record one explicitly selected development Supabase project reference, private bucket, schema/table set, Pinecone project/index ID and host, region, and a unique run prefix. Do not reuse or overwrite an index because its name resembles historical `neuvetra-kb`. Use two synthetic access scopes, A and B, and two non-admin test identities. Keep customer files, production resources and existing product auth flows out of this slice. The server derives scope from authenticated membership; the request accepts a question, not an index, namespace, storage path or arbitrary filter. Provisioning/ingestion credentials remain outside frontend code and request logs.

**Embedding candidate.** To avoid silently inheriting the legacy OpenAI dependency, the proposed first profile is Pinecone integrated `llama-text-embed-v2`, **1024 dimensions, cosine**, exact field map `text -> text`, document `input_type=passage`, query `input_type=query`, and `truncate=NONE` on both paths. The coordinator/CTO must adopt and verify this profile before creation; an unavailable model is a blocked choice, not permission to switch providers. Pin the selected SDK and API version (current reference is `2026-04`) and persist the live index/model description plus a canonical configuration hash. A different profile requires a new build/index and re-embedding. The provider model identifier is not a cryptographic weight revision; do not claim bitwise model reproducibility. Pinecone documents these model parameters and integrated embedding for both writes and searches. [Model description](https://docs.pinecone.io/reference/api/2026-04/inference/describe_model), [integrated index API](https://docs.pinecone.io/reference/api/2026-04/control-plane/create_for_model), [input truncation controls](https://docs.pinecone.io/guides/index-data/create-an-index).

**Supabase is authoritative.** Use versioned migrations for proposed `research_releases`, `research_passages`, `research_objects`, `research_ingestion_runs` and the minimal server-managed membership relation. Every release/passage/object row carries `scope_id`; composite foreign keys prevent joining another scope's release or object. Store immutable source PDF, normalized extraction and exact release bytes in a private bucket at scope-prefixed, content-addressed keys; Storage policies bind the bucket and scope prefix to membership. Object rows retain kind, SHA-256, size and key; passage rows retain release/source/extraction IDs and hashes, exact text/hash, locator/span metadata, dependencies, qualifications and review state. These rows are a validated projection of the pinned release, not editable approval authority. Preserve the old release's bytes/local-path fields; use a separate cloud-object mapping rather than rewriting its hash. Store upload/build state separately from domain approval.

For the synthetic test, metadata and `storage.objects` policies permit authenticated membership-scoped reads only; ordinary identities cannot upload, edit, delete, set approval or edit membership. Anonymous access is denied, including object listing/download. Set grants and RLS together in the migration. Keep the broad secret/service-role key confined to explicit provisioning/ingestion; test the runtime using the actual restricted reader identity, not that bypass credential. If the runtime instead uses a bypass key, RLS cannot be reported as its tenant defense and this contract needs a separate server-authorization review. Private buckets enforce access control on downloads; public buckets bypass it. [Database grants and RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage access control](https://supabase.com/docs/guides/storage/security/access-control), [bucket access models](https://supabase.com/docs/guides/storage/buckets/fundamentals), [key privileges](https://supabase.com/docs/guides/getting-started/api-keys).

**Pinecone is derived retrieval.** Namespace = server-owned scope plus immutable ingestion build ID; metadata filters include the exact release hash and embedding-profile hash. Each vector record has a deterministic ID derived from scope, release hash and passage ID, with text/hash and source identifiers. Namespace/filter values come only from the authorized build manifest. Results supply candidate IDs, never trusted approval, replacement paragraph text or object URLs. Re-resolve every hit through authorized Supabase rows and verified original/extraction bytes; validate complete dependency closure before context or display. Missing membership, empty/foreign namespace, absent result, hash mismatch, expired review, pending source or unavailable store returns an explicit no-result/unavailable state. Never retry in a default/global namespace, remove filters, add the old catalog, or silently fall back to local files. Pinecone operations target a namespace; namespace selection is still the application's authorization responsibility. [Namespaces](https://docs.pinecone.io/guides/index-data/implement-multitenancy), [metadata filters](https://docs.pinecone.io/guides/search/filter-by-metadata).

**Idempotent activation.** Ingestion is an explicit dry-run/apply operation, never import/startup work. Create immutable objects without overwrite, stage validated rows, upsert deterministic record IDs, then fetch/resolve the expected records before transactionally activating the build pointer. A repeated identical manifest converges without additional logical rows; same identity with different bytes is a conflict. Do not assume a database transaction includes Storage or Pinecone. Failed/interrupted uploads leave the build inactive; a bounded resumable job records completed stages. Poll readiness with a finite deadline, not a fixed sleep as evidence. Pinecone upsert replaces an existing ID and visibility is eventually consistent; Supabase supports overwrite but this contract deliberately uses new content-addressed paths. [Upsert semantics](https://docs.pinecone.io/guides/index-data/upsert-data), [freshness checks](https://docs.pinecone.io/guides/index-data/check-data-freshness), [Storage upload behavior](https://supabase.com/docs/guides/storage/uploads/standard-uploads).

## Required evidence: one small real integration run

Freeze the code, migration, synthetic fixture and resource/build manifest before execution. Seed six synthetic passages split across A/B, including one dependency pair and one inactive record. The test runner must record real provider request IDs/counters and sanitized outcomes; mocks establish fault handling separately and cannot be labeled cloud proof.

| Check | Acceptance evidence |
| --- | --- |
| Configuration | Described development targets match the pinned model, dimensions, metric, field map and read/write parameters. Wrong host/profile and overlong non-truncating input fail explicitly. |
| Storage lineage | Download every seeded object through its authorized reader; all byte hashes/sizes match. Reconstruct every span by the pinned normalization/code-point convention; exact passage text and dependencies match. |
| Supabase permissions | A can read A. Anonymous and B cannot list/read A rows or objects, request its download link, or mutate data/approval/membership. Tests use actual JWT identities; broad-key success is not an RLS test. |
| Pinecone isolation | Identical A/B query text returns only the authorized namespace/release; same-scope inactive records are excluded. Foreign namespace/filter input is rejected before dispatch. No default/global query appears in request evidence. |
| Idempotency/failure | Apply the identical seed twice with unchanged logical counts and hashes. Interrupt after object upload and after vector write: neither build becomes active. A changed-byte identity is refused. Resume reaches one complete build. |
| Retrieval and citation | Three frozen semantic paraphrases retrieve their required synthetic passage/dependency IDs at fixed `top_k=4`; no exact ordering is required. Browser/API output resolves to exact stored passage text, source identity, locator and authorized original bytes. Local source resolution is disabled for this run. No generation call is needed. |
| Fail-closed boundaries | Controlled missing/corrupt source, missing dependency, expired review and wrong-scope returned hit expose no answer or unauthorized text. A source-store/vector-store outage has no alternate-store fallback. Record which cases are live development faults and which are adapter mocks. |
| Cleanup/rollback | Deactivate the test build first, remove only manifest-owned vector IDs and unreferenced test objects/rows, then verify absence after propagation; B/control objects remain unchanged. Restoring the prior verified pointer or leaving no active build works. No project/index-wide deletion is needed. |

A signed storage URL is a temporary bearer capability; authorize before issuing it, keep it short-lived and exclude it from durable logs. Prefer the verified publisher URL plus page locator for public originals; synthetic private originals need the authorized download route. Hash metadata alone is insufficient: the downloaded bytes and resolved span must match.
